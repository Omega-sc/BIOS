## 1. Deliverables Breakdown

### Phase A: State and Plain Python State Machine
1. **Pipeline State (`agent/state.py`)**:
   - `IncidentState` (Pydantic v2 model) tracking execution state across pipeline nodes:
     - Telemetry and ingestion: `db_path`, `mode`, `clock_offsets`, `spans`, `logs`, `metrics`, `metric_onsets`.
     - Topology and frontier: `dag`, `failure_frontier`.
     - Hypotheses and scores: `hypotheses`.
     - Simulator and counterfactuals: `sim_params`, `counterfactuals`.
     - Timeline and final post-mortem report: `timeline_events`, `report`.
     - Tracing and messaging: `step_count`, `events`, `messages`.
   - Backward-compatibility alias: `InvestigationState = IncidentState`.
2. **Deterministic State Machine Pipeline (`agent/runner.py`)**:
   - Pure Python generator pipeline (no heavyweight LangGraph dependencies):
     `telemetry_ingestion -> topology_builder -> hypothesis_generator -> counterfactual_verifier -> report_synthesizer`
   - Yields `AgentEvent` objects (`type="state"`, `"tool_call"`, `"tool_result"`, `"hypothesis"`, `"report"`).
   - In `scripted` mode: invokes all P2 analytical tools (`estimate_clock_offsets`, `rank_metric_onsets`, `get_metric_derivatives`, `query_spans`, `build_dependency_dag`, `failure_frontier`, `fit_sim_params`, `run_counterfactual`).

### Phase B: Scoring, Validation, and Synthesis
1. **Likelihood Ratio Confidence Scoring (`agent/scoring.py`)**:
   - Formulates and evaluates candidate hypotheses H1-H4 dynamically against SQLite telemetry in clock-corrected coordinates without reading ground truth:
     - **H1 (Auth connection pool leak)**: Pool active connections surge to saturation while queries in flight remain flat; pool onset precedes gateway 5xx onset; auth error logs confirm unhandled exceptions skipping release (`skipped release()`); DB query durations remain fast and unchanged.
     - **H2 (Frontend retry storm origin)**: Compares frontend CPU onset against gateway error onset; demonstrates frontend retry cascade occurred 30s after gateway 504 onset, making it a contributing factor rather than root cause.
     - **H3 (Slow DB queries)**: Evaluates queries in flight and database span execution durations; refuted by flat queries in flight and fast healthy DB query duration.
     - **H4 (Gateway timeout too low)**: Evaluates whether downstream was healthy; refuted by pool saturation and auth timeout errors.
   - Loads likelihood-ratio weights from `eval/fitted_weights.json` if available, normalizing candidate posteriors to sum to 1.0.
   - Cites actual `EvidencePointer` objects resolving directly to real rows in the SQLite database.
   - Dynamically designates `root_cause` based on evidence rather than hardcoded assumptions.
2. **Contract and Evidence Validation (`agent/validate.py`)**:
   - `validate_evidence_pointer`: Verifies that every cited evidence pointer resolves to a real row in SQLite (spans table for `span_id`, logs table for `log_id`, metrics table for `metric@ts_ms` supporting exact, sampling-window, and clock-skew-corrected timestamps).
   - `enforce_claim_types`: Strictly checks that timeline events with `claim_type == "verified_fact"` have resolving evidence pointers; otherwise automatically demoted to `"inference"`.
   - `validate_timeline_events`: Ensures chronological ordering (`t_corrected_ms` ascending).
   - `validate_incident_report`: Full structural and semantic audit ensuring root cause is established, timeline is ordered and evidenced, all evidence pointers in timeline events and hypotheses resolve, and remediations are concrete.
3. **Structured Incident Report Synthesis (`agent/nodes/report_synthesizer.py`)**:
   - `synthesize_incident_report`: Reconstructs clock-corrected, chronological timeline events with verified facts vs inferences.
   - Produces contract-compliant `contracts.models.IncidentReport` containing:
     - Chronological timeline events
     - Evaluated hypotheses with root cause and contributing factor
     - Evidence pointers (100% resolving to real rows)
     - Estimated clock offsets in seconds
     - Actionable remediations (sane max_pool_size, release in finally/context managers, pool leak watchdog alerts, exponential backoff with jitter, gateway circuit breaker).

### Phase C: Counterfactual Verification and LLM Tool-Calling
1. **Counterfactual Verifier Node (`agent/nodes/counterfactual_verifier.py`)**:

   - Standard Anthropic Messages multi-turn tool calling formatting with `tool_use` and `tool_result` blocks.
   - Deterministic tool-calling fallback covering all investigation tools for offline environments and automated CI.
3. **Prompts and System Directives (`agent/prompts.py`)**:

## 2. Investigation Execution Modes

The agent pipeline supports three modes via `run_investigation(db_path: str, mode: str) -> Iterator[AgentEvent]`:

### 1. Scripted Mode (`mode="scripted"`, Default)
Deterministic rule-based investigator executing the 5-node pipeline:
```python
from agent.runner import run_investigation

for event in run_investigation("data/incident.db", mode="scripted"):
    if event.type == "state":
        print(f"Node: {event.node} ({event.payload.get('status')})")
    elif event.type == "hypothesis":
        print(
            f"Hypothesis {event.payload['id']}: {event.payload['verdict']} (score: {event.payload['confidence']:.2f})"
        )
    elif event.type == "report":
        print("Report received:", event.payload["schema_version"])
```

### 2. Replay Mode (`mode="replay"`)
100% offline, zero-network, instantaneous streaming from frozen recordings in `fixtures/replay/`:
```python
from agent.runner import run_investigation

# Replays pre-recorded events for UI demos and offline benchmarking
events = list(run_investigation("data/incident.db", mode="replay"))
```

### 3. Live Mode (`mode="live"`)
Autonomous tool-calling loop using `LLMAdapter` with caching, multi-turn tool schema formatting, and contract validation retry:
```python
from agent.runner import run_investigation

# When ANTHROPIC_API_KEY is set, queries Claude 3.5 Sonnet; otherwise uses deterministic fallback.
# In both cases, responses are cached in fixtures/replay/llm_cache.json.
events = list(run_investigation("data/incident.db", mode="live"))
```
