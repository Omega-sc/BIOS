## 1. Deliverables Breakdown

### Phase A: Core Analytical Tools
1. **Clock Skew Estimation (`tools/skew.py`)**:
   - `estimate_clock_offsets(db) -> dict[str, float]`: Estimates per-service clock skew by measuring cross-service parent->child span start deltas (`child.start_ms - parent.start_ms`) during healthy baseline (`status_code == 200`), subtracting minimal network/dispatch transit latency (~2ms).
   - Root service (`gateway`) serves as 0.0s reference clock.
   - Computes clock skew dynamically from data without ever reading `contracts.constants.SKEW_MS` or ground truth.

2. **Causal Span Queries & Orphan Detection (`tools/spans.py`)**:
   - `query_spans(db, service=None, status_code=None, time_window=None, trace_id=None, causal=True, limit=None) -> list[Span]`:
     - Clock correction: sets `t_corrected_start_ms = start_ms - int(offset_s * 1000)` under `causal=True`.
     - Orphan detection: flags `orphan=True` if `parent_span_id` is present but no parent span exists in the database.
     - Causal ordering: orders traces chronologically by gateway root span start time; orders spans within each trace via DFS over the `parent_span_id` tree.
     - Time window filtering: filters by `w_start <= t_corrected_start_ms <= w_end` in corrected time coordinates.
     - `fetch_causal_spans(db, trace_id)` helper alias.

3. **Metric Derivatives & Chronological Onset Detection (`tools/metrics.py`)**:
   - `get_metric_derivatives(db, metric_name: str) -> MetricOnset`:
     - Corrects metric timestamps with estimated service clock offset.
     - Smooths sensor noise via rolling median filter (window=7, center=True).
     - Computes numerical gradient with respect to time in seconds ($d(\text{metric})/dt$).
     - Establishes baseline mean and standard deviation over early samples ($N=35$).
     - Identifies onset as the first point where derivative exceeds baseline mean + 4σ for 3 consecutive samples.
   - `rank_metric_onsets(db) -> list[MetricOnset]`: Returns all metrics sorted chronologically by anomalous onset timestamp (`onset_corrected_ms`), with uninflected metrics placed at the end.

4. **Dependency DAG & Failure Frontier (`tools/dag.py`)**:
   - `build_dependency_dag(db) -> nx.DiGraph`:
     - Nodes annotated with `error_rate`, `metric_onset`, `span_count`.
     - Edges annotated with `call_count`, `mean_latency` (ms), and `error_propagation_fraction`.
   - `to_node_link_json(dag) -> str`: Exports NetworkX graph to standard node-link JSON format.
   - `failure_frontier(dag, db) -> str`: Pinpoints `"auth-service -> db-pool"` by detecting the connection pool leak signature (`db_pool.active_connections` saturated while `db_pool.queries_in_flight` flat).

### Phase D: Discrete-Event Simulator & Counterfactuals
- **Simulation Parameter Fitting (`sim/fit.py`)**:
  - `fit_sim_params(db) -> SimParams`: Dynamically estimates parameters from SQLite telemetry:
    - Arrival rate: $1.63\text{ req/s}$ (derived from gateway root span throughput).
    - Mean service time: $29.8\text{ ms}$ (derived from successful db acquire durations).
    - Leak probability: $0.0332$ (unreleased acquires from auth error logs / total acquires adjusted for log drop; matches both `acquire_connection` and `get_connection`).
    - Pool size: $20$ connections (`POOL_MAX`).
    - Gateway timeout: $3000\text{ ms}$ (with fallback to 504 span duration); Acquire timeout: $5000\text{ ms}$.
- **Fast Discrete-Event Simulation (`sim/pool_sim.py`)**:
  - `simulate_pool(params, n_runs=300)`: Models Poisson arrivals, FIFO wait queue, connection acquisition from pool, permanent leak retention, acquire/gateway timeouts, and exponential retry backoff.
  - Highly optimized: 300 Monte Carlo runs execute in $\approx 0.45\text{s}$ (well within the $< 1.0\text{s}$ budget for real-time UI sliders).
- **Counterfactual Interventions (`sim/interventions.py`)**:
  - `run_counterfactual(params, intervention, n_runs=300) -> CounterfactualResult`:
    - `"fix_leak"`: Sets `leak_prob = 0.0`. Failure probability drops from baseline $0.478$ to $0.000$ (CI: $[0.0, 0.0]$). Proves leak is root cause.
    - `"pool_size=50"`: Scales pool capacity to 50. Failure probability drops to $0.000$ over the incident window, delaying exhaustion.
    - `"no_retries"`: Sets `retry_max = 0`. Failure probability remains elevated ($0.223$), proving retries are an amplifier rather than root cause.

## 2. Interface Semantics and Units

| Field / Output | Unit | Semantics / Coordinates |
| :--- | :--- | :--- |
| `estimate_clock_offsets` | Seconds (`float`) | Offset $\Delta$ such that $t_{\text{true}} = t_{\text{local}} - \Delta \cdot 1000$. |
| `t_corrected_start_ms` | Epoch ms (`int`) | Clock-corrected span start time aligned across all services. |
| `time_window` in `query_spans` | Epoch ms (`tuple[int, int] | list[int]`) | Bounds evaluated against `t_corrected_start_ms`. |
| `orphan` in `Span` | Boolean | `True` if `parent_span_id` is set but parent span is missing in database. |
| `MetricOnset.onset_corrected_ms` | Epoch ms (`int | None`) | First timestamp where rolling median derivative exceeds baseline mean + 4σ for 3 consecutive samples. |
| `MetricOnset.peak_slope` | Value / second (`float`) | Maximum numerical gradient over smoothed series. |
| `build_dependency_dag` edges | Calls, ms, fraction | `call_count` (`int`), `mean_latency` in ms (`float`), `error_propagation_fraction` in $[0, 1]$ (`float`). |
| `SimParams.arrival_rate_per_s` | Requests / second (`float`) | Poisson arrival intensity. |
| `SimParams.mean_service_ms` | Milliseconds (`float`) | Mean connection hold duration. |
| `SimParams.leak_prob` | Probability $[0, 1]$ (`float`) | Fraction of connection acquires unreleased on exception. |
| `CounterfactualResult.ci95` | Probabilities $[0, 1]$ | 95% confidence interval `(ci_low, ci_high)` over Monte Carlo iterations. |
